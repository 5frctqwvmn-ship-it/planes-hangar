PLANES HANGAR VIDEO — v6 BRIEF

GOAL
Re-cut the Planes Hangar explainer so it sounds like a friendly host showing one visitor around an airfield, not a narrator reading notes. Keep the Mr. DNA (Jurassic Park, 1993) approach: one metaphor, one idea per shot, the picture says it first, sincere and never sarcastic.

BASE CUT
Build from cut-v5 (long), not cut-v5-short. The short cut drops the baggage/tug jobs and the line "Started with planes, ended with planes," which makes it feel more rushed, not less. Target runtime: 90–110 seconds.

WHAT TO FIX

1. Pacing
- The script is written as strings of 3–5 word fragments ("Better trucks. Usage bars. A phone fit."). TTS reads those at one flat speed with identical pauses. Merge related fragments into full sentences.
- Every question and every reveal gets silence after it. Key lines: "Running what?", "Yikes!", "That's me, making this video."
- Vary the speed. Faster on excitement, slower and lower-pitched on the one line per section that carries the point ("So you learn what things really cost," "Started with planes, ended with planes").
- Generate the voice in 4–5 separate chunks (Intro / How it works / Tower / Evolution / Sunday + close). Long single passes flatten and speed up.
- Do NOT rely on "…" or [beat] tags to produce pauses. Insert real silence in the edit. Do not speak bracketed directions aloud.
- Pause guide (starting points, adjust to picture): 0.3–0.5s between related thoughts; 0.6–1.0s after a question or new definition; 1.5s on the Sunday time-lapse with sound effect only.
- If a section still feels crowded, cut words or extend the shot. Never speed up the voice.

2. Comprehension
- Open by stating the relationship: we were building a plane game for a four-year-old with AI agents; we couldn't see what the agents were doing; so we built them an airfield to watch. Viewers currently can't tell if this is the kid's game or a dashboard.
- Teach three things before any detail: planes are agents; ground vehicles show what each agent is doing; the tower coordinates. Then follow ONE agent through ONE job (request → tower assigns → crew rolls out → status and cost update).
- Cut undefined jargon or replace it with what's on screen: "a phone fit," "pads," "tool call," "usage bars." If a word has no object on screen, cut the word.
- Name what "the number" actually measures (e.g., CPU). Don't say "the computer working hard."
- "Carts" currently means two things (director's own work, then the traffic jam). Use one meaning.
- Keep amber = "thinking" (do not change what the UI means). Fix the overlap with the fuel truck in the writing: amber flashes while it thinks; when it calls a tool, the ground crew rolls out.
- Shrink the build history to one beat: it got crowded → Yikes → we organized it. No version-by-version changelog.

3. Visual timing
- Highlight each object on screen before or as its name is spoken. Don't introduce the next object until the current one is readable.
- Leave a few demonstrations silent.
- Credits ("Made by MJ and his son…") go on a card with music. Do not narrate them.

4. Voice direction
Warm, quick, light Texan drawl. Small-town science teacher who loves the exhibit. Talk to one curious visitor. Contractions, short full sentences. Questions sound genuinely curious. Reveals are pleased and understated, not shouted. Sincere, never winking. Keep "Howdy," "partner," "Hold onto your hubcaps," "Yikes!" — but they are seasoning, not the structure.

NOTES ON THE SCRIPT
- Fuel truck is written as "loading up" so it no longer duplicates amber = thinking. If the fuel truck truly represents thinking in the app, keep "That's it thinking" and cut the amber line instead. Don't let two things mean "thinking."
- Replace [CPU / actual metric] with whatever the number really is.
- Alternate closing line if "a game of its own" feels too neat: "We built a game for a four-year-old. [beat] Then we built one for his dad."

DELIVERABLES
1. Voice: 5 chunks, with the above pauses inserted in the edit.
2. Picture: object highlighted before it's named; one idea per shot; Sunday time-lapse with SFX only; credits on a card.
3. Before final render, run the mute test: with sound off, can a first-time viewer still follow request → tower → crew → status → cost? If not, fix the picture, not the narration.

SUCCESS TEST
Sound off: the process is clear. Picture off: the narration makes sense. The host sounds like he's showing you something, not reading it.

OTHER THINGS TO THINK ABOUT
(Notes from a second and third reviewer. Not required changes. Weigh them, then raise them with MJ in the questions below.)

Pacing and delivery
- Sentences in v5 never drop in pitch at the end, so the ear never gets a "thought finished" signal. Ask the voice tool for falling intonation on statements, rising only on real questions.
- "Yikes!" should interrupt the sentence like a reaction, not sit inside it as a word.
- Give different line types different deliveries: hooks curious, definitions slower and grounded, jokes underplayed on the setup, reveals paused then pleased, takeaways plainer with less character acting.
- Let sound effects create pauses the way Mr. DNA stops talking for the drill. Candidates: a radar beep on "Running," a tire screech on "Traffic jam," a tape fast-forward zip on the Sunday time-lapse.
- Add 400–600ms of room tone between paragraphs so the eye can find the object before the voice names it.

Comprehension
- Consider a zoom-in order instead of a list: tower (plans) → plane (one agent) → ground crew (what it's doing) → price tag (what it costs). Big picture to detail.
- Translate developer vocabulary into on-screen events: "every tool call" becomes "every time an agent reads a file or runs a command."
- "Our cheapest agent" puts price before purpose. Alternative: "a lightweight agent keeps the board updated, so the director can focus on the work."
- "The real bill" could imply an actual invoice. If the system reports tracked usage, say "the real number" or "the recorded cost."
- "Started with planes, ended with planes" only works if viewers remember the agents were planes at the start. Make sure the opening shot establishes that clearly.

Mr. DNA fidelity
- The charm comes from delighted demonstration, not cowboy vocabulary. If a catchphrase sits on every transition, thin them out. "Running what?" is essential; "Hold onto your hubcaps" is optional.
- Mr. DNA never narrates how his own cartoon was redesigned. The build-history section is the single biggest drift from the reference. If it stays, it should be three shots, not eight sentences.
- The original ends on the product (the hatching egg), not the process. "Go check on your crew" is the right button; keep it last.
- A reviewer that read only the transcript scored v5 around 6.5/10 overall: concept 8, persona 8, comprehension 6, pacing 4–5. No reviewer heard the audio, so treat the pacing score as an estimate until you listen yourself.

Production
- One reviewer preferred the short cut for its lower clutter, then reversed after noticing it lost the rhythm and the best line. If runtime pressure returns, cut the build history, not the crew assignments.
- Different TTS tools treat "…" and em-dashes differently. Test one paragraph first and confirm the pauses actually appear before generating all five chunks.

QUESTIONS TO ASK MJ BEFORE STARTING
(Read the whole brief first, then ask these in one message. Each answer changes the output as noted.)

1. Audience: Is this for other developers, for a general audience (friends, LinkedIn, the kid's grandparents), or for a product launch? → Decides how much jargon survives ("tool call," "orchestrator," CPU) and whether the developer humor stays in.

2. Runtime ceiling: Is 90–110 seconds acceptable, or is there a hard limit (e.g., 60s for a short-form platform)? → If under 75s, the build history gets cut entirely and the close shrinks to the question plus "game of its own."

3. UI truth check: What exactly do these mean in the app: amber light, fuel truck, "the number," the tag's two values, the carts by the tower? → Prevents the script from inventing meanings. Any mismatch means a rewrite of the "How it works" section.

4. Build history: Keep it as one beat, cut it, or expand it as the actual story of the project? → Keep = current script. Cut = 15 seconds shorter and tighter. Expand = this becomes a maker's-journey video, not a Mr. DNA explainer, and the voice direction changes.

5. Closing line: "The game we were building turned into a game of its own" or "We built a game for a four-year-old, then we built one for his dad"? → First is cleaner and safer. Second is more personal and sets up the credits card better but shifts the tone toward family story.

6. Gaming angle: How much weight on "it becomes a game that makes you want to build more"? One line, or a short visual beat showing you adding a job just to watch the planes? → A visual beat adds 5–8 seconds but proves the claim instead of stating it.

7. Catchphrase density: Keep all of "Howdy," "partner," "Hold onto your hubcaps," "Yikes!"? Or trim to two? → Full set leans theme-park mascot. Trimmed leans warm host. Both are valid; pick one deliberately.

8. Voice tool and controls: Which TTS tool, and does it support SSML or explicit pause tags? → Determines whether pauses go in the script or get added as silence in the edit.

9. Self-reference: Keep "That plane? That's me, making this video"? → It's the best fourth-wall moment, but only works if the plane is visibly highlighted at that second. If the picture can't support it, cut it rather than leave it unsupported.

10. Credits: Card only, or card with a quiet spoken sign-off after a 1.5s pause? → Card only keeps the character intact. Spoken version is warmer but risks sounding like the actor read the stage directions.

11. Priority if something has to give: pacing, comprehension, or Mr. DNA fidelity? → If pacing wins, extend shots and cut words. If comprehension wins, add the one-agent-one-job walkthrough even if it costs 10 seconds. If fidelity wins, cut the build history and lean into sound-effect pauses.
